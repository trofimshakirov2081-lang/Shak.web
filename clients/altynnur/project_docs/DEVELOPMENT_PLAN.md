# АлтынНур: план разработки

План исходит из рекомендованного стека (OPEN_QUESTIONS №1-4). Если Трофим выберет другой вариант, меняются этапы 1, 2, 4 и 15, остальное остаётся.

## Предлагаемый стек
| Слой | Решение | Почему |
|---|---|---|
| Хостинг | Beget (РФ), домен клиента, HTTPS (Let's Encrypt от Beget) | ПДн хранятся в России (152-ФЗ). Дёшево. Есть опыт с Эмирэлд |
| Backend | PHP 8.x, свой маленький роутер, JSON API `/api/*`, PDO | Серверная проверка прав, секреты в `config.php` вне веб-корня |
| БД | MySQL 8 (utf8mb4), миграции в `db/migrations/*.sql` + раннер | Воспроизводимая схема (Ч10 §5) |
| Публичные страницы | PHP рендерит HTML из опубликованного снимка | SEO: мета, JSON-LD, 404, 301, sitemap (Ч7) |
| Интерактив сайта | Vanilla JS (ES-модули) поверх готового HTML | Быстро, без тяжёлых библиотек (Ч7 §9.3) |
| Админка | SPA на Preact + htm, файлы в проекте, без сборки. Альтернатива: Vite + TS | Сложный UI (редактор, Kanban, D&D) без шага сборки |
| Стили | CSS custom properties (design tokens), генерация `tokens.css` из `design_settings` при публикации | Одна система токенов (Ч4 §2) |
| Медиа | Файлы на сервере, обработка GD/Imagick → WebP (+AVIF, если есть), 3-4 размера | `srcset`, оптимизация (Ч5 §16) |
| Auth | Сессии PHP (HttpOnly, Secure, SameSite), `password_hash`, лимит попыток, CSRF-токен, сброс по email | Проверенные механизмы (Ч8 §3, §18) |
| Уведомления | Очередь в БД + cron каждую минуту → Telegram Bot API и SMTP | Заявка не зависит от каналов (Ч6 §13) |
| Тесты | PHPUnit (API, права), Playwright (E2E, ширины, скриншоты 390px) | Ч10 §17 |

## Фазы по приоритетам (Ч10 §26)
- **Фаза 1, MVP «Под ключ»:** этапы 1-6, 10 (без Kanban и аналитики), 13, 14, 15. Рабочий сайт, админка, курсы, блоки, публикация, заявки, безопасность, адаптив.
- **Фаза 2:** этапы 7, 8, 9, 10 полностью (Kanban, квиз-конструктор, аналитика), 11, 12. Визуальный редактор, полный дизайн, CRM, SEO, галерея, история, копии.
- **Фаза 3:** продвинутые анимации и эффекты, расширенная аналитика, доп. интеграции, блог.
- После всего: этап 16, аудит по Ч11.

Объём фаз 2 и 3 и их цена «по договорённости» (OPEN_QUESTIONS №3).

## Этапы

### 1. Архитектура и основа проекта
- **Цель:** каркас, в который ложатся все модули.
- **Зависимости:** решения по OPEN_QUESTIONS №1-5.
- **Что сделать:**
  - структура папок `public/` (веб-корень: index.php, assets), `app/` (роутер, контроллеры, сервисы, репозитории), `admin/` (SPA), `db/migrations/`, `config/`, `tests/`, `docs/`;
  - `.env.example`, `.gitignore`;
  - ADR-файл архитектурных решений `docs/DECISIONS.md`;
  - `PROJECT_STATUS.md`.
- **Готово, если:** локальный запуск (`php -S` + MySQL в Docker или локально) открывает пустую страницу и `/api/health`.

### 2. База данных и API-ядро
- **Цель:** схема и безопасный доступ к данным.
- **Зависимости:** 1.
- **Что сделать:**
  - миграции всех сущностей из MASTER §2 (сразу целиком, чтобы не перекраивать);
  - сид-данные: контакты, 7 курсов, 3 категории, тема «Ночное золото», стартовые блоки главной, 10 FAQ, тексты по умолчанию, 3 вопроса квиза, 10 статусов лидов;
  - роутер API, валидация, единый формат ошибок, журнал ошибок;
  - разделение публичных и приватных эндпоинтов.
- **Файлы:** `db/migrations/*`, `db/seed/*`, `app/Http/*`, `app/Repo/*`.
- **Готово, если:** миграции накатываются с нуля, сиды грузятся, PHPUnit проверяет CRUD и что приватные таблицы недоступны без сессии.

### 3. Дизайн-система (база)
- **Цель:** токены и компоненты, на которых строится всё.
- **Зависимости:** 2.
- **Что сделать:**
  - `tokens.css` из `design_settings` (цвета с ролями, типографика `clamp()`, радиусы, тени, отступы, glass);
  - механизм наследования Тема > Страница > Блок > Элемент через CSS-переменные на обёртках;
  - базовые компоненты: кнопки 6 типов, карточки, поля, аккордеон, модалка, слайдер;
  - шрифты WOFF2 self-hosted (Playfair Display, Ysabeau Office);
  - план дизайна по навыку `frontend-design` и обзор 5-8 лучших beauty-академий, запись в ДИЗАЙНЫ.md.
- **Файлы:** `public/assets/css/*`, `app/Design/*`.
- **Готово, если:** смена цвета или радиуса в БД меняет страницу после публикации, контраст проверен.

### 4. Публичная часть
- **Цель:** сайт, который можно показать.
- **Зависимости:** 2, 3.
- **Что сделать:**
  - PHP-рендер страниц из блоков (порядок, видимость, шаблоны вида);
  - все блоки главной (MASTER §3), страница курса, каталог с фильтрами без перезагрузки, преподаватель, галерея, контакты, политика, 404;
  - формы (с отправкой из этапа 6);
  - мобильная композиция, без fixed внизу;
  - пустые состояния скрываются.
- **Файлы:** `app/Render/*`, `app/Blocks/*`, `public/assets/js/*`.
- **Готово, если:** проверены все страницы на 11 ширинах, скриншоты 390px, нет undefined/null, порядок блоков из БД (контакты первыми → страница начинается с контактов).

### 5. Авторизация и админ-оболочка
- **Цель:** защищённый вход и каркас админки.
- **Зависимости:** 2.
- **Что сделать:**
  - вход, выход, сброс пароля по email, смена пароля, лимит попыток, CSRF, проверка прав на каждом API-запросе;
  - роли (используется только Владелец);
  - оболочка SPA: меню групп, Dashboard (счётчики, последние действия, быстрые действия, состояние), центр предупреждений, мобильная навигация;
  - журнал действий;
  - ссылка «Админка» в футере.
- **Готово, если:** без входа API отдаёт 401, ни один приватный эндпоинт не открывается, тесты безопасности Ч8 §20 «Доступ» зелёные.

### 6. Контент, курсы, медиатека, публикация (ядро CMS)
- **Цель:** владелица меняет всё содержимое.
- **Зависимости:** 4, 5.
- **Что сделать:**
  - редакторы: курсы (8 вкладок), категории, программы (модули и темы, D&D + кнопки), наборы (список; календарь в фазе 2), преподаватель, отзывы, FAQ, преимущества, бонусы, акции, контакты, юр. документы;
  - медиатека с обработкой фото;
  - структурный редактор блоков главной (добавить, скрыть, дублировать, удалить, порядок);
  - черновики, предпросмотр (ПК, планшет, телефон), атомарная публикация через снимок `page_versions`, история и откат, корзина, автосохранение, предупреждения о незаполненном.
- **Готово, если:** проходят сценарии Ч5 §23 (кроме календаря и массовых операций фазы 2), E2E 5-13.

### 7. Полная настройка дизайна (фаза 2)
- **Цель:** раздел «Дизайн» Ч4 целиком.
- **Зависимости:** 3, 6.
- **Что сделать:**
  - палитры и роли, проверка контраста, типографика по уровням, скругления, Liquid Glass по компонентам, карточки, кнопки и состояния, фоны, тени, отступы по устройствам, изображения с фокальной точкой, иконки;
  - темы с экспортом и импортом JSON, undo и redo;
  - разделённый экран с живым предпросмотром.
- **Готово, если:** пройдены 28 сценариев Ч4 §26.

### 8. Визуальный и inline-редактор (фаза 2)
- **Цель:** правка кликом по странице.
- **Зависимости:** 6, 7.
- **Что сделать:**
  - режим редактирования поверх реального рендера в iframe предпросмотра: рамки, подсказки, панель с вкладками Контент, Изображение, Дизайн, Ссылка, Дополнительно;
  - синхронизация со структурным режимом через те же данные;
  - D&D мышью и тачем.
- **Готово, если:** Ч11 §9: клик по заголовку → правка → публикация → видно на сайте.

### 9. Расширенный контент (фаза 2)
- **Что сделать:** галереи и до/после с проверкой согласий, календарь наборов, глобальный поиск, массовые действия, история ключевых полей (прошлые цены), инфо-страницы из блоков, библиотека блоков с поиском, шаблоны вида.
- **Зависимости:** 6.
- **Готово, если:** закрыты оставшиеся сценарии Ч5 §23 и Ч3 §59.

### 10. Заявки, квиз, CRM
- **Цель:** ни одна заявка не теряется.
- **Зависимости:** 4, 5.
- **Что сделать:**
  - фаза 1: единый эндпоинт заявок (валидация, honeypot, rate limit, идемпотентность), согласие с версией, контекстные формы, квиз из 3 вопросов с рекомендациями из БД, список заявок, карточка, статусы, заметки, быстрые действия, опрос новых заявок, UTM;
  - фаза 2: Kanban, конструктор квиза, аналитика и конверсии, экспорт CSV/XLSX, свои статусы.
- **Готово, если:** проходят 28 пунктов Ч6 §24 (фаза 1: всё, кроме аналитики и экспорта), E2E 1-4, 14, 15.

### 11. Интеграции (фаза 1 частично, фаза 2 полностью)
- **Что сделать:**
  - фаза 1: очередь уведомлений + cron, Telegram-бот (токен в config), WhatsApp-шаблоны;
  - фаза 2: SMTP, Метрика с 11 событиями без дублей, GA по необходимости, раздел «Интеграции» с проверкой подключения и логами.
- **Зависимости:** 10.
- **Готово, если:** выключенный Telegram не мешает заявке, в админке виден статус доставки, тестовое сообщение приходит.

### 12. SEO и аналитика
- **Что сделать:**
  - фаза 1: Title, Description, canonical, OG, Schema.org (организация, курсы, крошки), sitemap и robots из PHP, 404 с кодом, 301 при смене slug;
  - фаза 2: SEO-раздел с предпросмотром сниппета и подсказками, менеджер редиректов, проверка alt, верификация Вебмастера и Search Console, инструкция для Айгуль.
- **Зависимости:** 4, 6.
- **Готово, если:** 25 пунктов Ч7 §21, Rich Results Test и Schema Validator без ошибок, PageSpeed проверен на мобильном.

### 13. Безопасность и надёжность
- **Что сделать:**
  - аудит RLS-аналога (проверки прав в каждом контроллере);
  - санитайзер HTML (белый список);
  - проверка загрузок по MIME и реальному формату;
  - заголовки безопасности (CSP, X-Frame-Options кроме предпросмотра);
  - резервные копии (cron-дамп + раздел в админке, восстановление с контрольной копией);
  - мониторинг состояния;
  - хранение и удаление заявок;
  - SECURITY.md.
- **Зависимости:** все предыдущие этапы фазы.
- **Готово, если:** зелёные все тесты Ч8 §20, нет секретов в репо и в выдаче.

### 14. Тестирование
- **Что сделать:**
  - PHPUnit: API, права, формы, публикация;
  - Playwright: 15 E2E-сценариев Ч10 §17, 11 ширин, скриншоты 390px;
  - ручная проверка админки с телефона;
  - тест цепочек «контент → публикация → сайт» и «заявка → CRM».
- **Зависимости:** 1-13.
- **Готово, если:** все тесты зелёные, отчёт в PROJECT_STATUS.

### 15. Запуск и передача
- **Что сделать:**
  - тариф Beget и домен, HTTPS и редирект, миграции на проде, config с секретами, cron;
  - проверка Storage, auth, интеграций, SEO, копий;
  - удаление тестовых данных, аккаунт Айгуль со сменой пароля;
  - README, ADMIN_GUIDE (простым языком), DEPLOYMENT;
  - безопасная передача доступов.
- **Зависимости:** 14.
- **Готово, если:** чек-лист Ч10 §23 пройден на боевом домене.

### 16. Финальный визуальный аудит (Ч11)
- **Что сделать:**
  - диагностика в браузере, проверка на шаблонность, hero, путь сомневающейся ученицы, мобильный аудит на 11 ширинах, админка от лица Айгуль;
  - список P0/P1/P2 → показать Трофиму → исправления по группам;
  - `FINAL_AUDIT_REPORT.md` с честной оценкой и списком материалов от Айгуль.
- **Зависимости:** 15 (или до запуска, если Трофим решит).
- **Готово, если:** выполнен критерий завершения Ч11 §18.
