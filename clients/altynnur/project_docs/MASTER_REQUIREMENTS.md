# АлтынНур: сводные требования

Основной рабочий документ. Детали и точные тексты в `PART_XX.md` (ссылки вида Ч5 §3), дословный исходник в `source/`. Конфликты и решения в `OPEN_QUESTIONS.md`.

## Сквозные правила (действуют везде)
1. **Никаких имитаций.** Каждая кнопка работает, сохранение реально пишет в БД, скрытие убирает с сайта, порядок переживает перезагрузку, файл реально загружается (Ч1 §13, Ч3 §59, Ч10 §1).
2. **Достоверность.** Не выдумывать: отзывы, фото работ и преподавателя, результаты, число выпускниц, стаж, образование, сертификаты, лицензии, рассрочку, места, расписание, адрес, гарантии трудоустройства и дохода. Пусто лучше выдумки, блок без данных скрыт (Ч2 §35, Ч5 §21, Ч10 §19).
3. **Контент отдельно от кода.** Всё видимое приходит из БД и меняется в админке (Ч1 §4.2, Ч3 §38, Ч10 §6).
4. **Один источник данных.** Цена, дата, контакт меняются в одном месте и обновляются везде (Ч2 §37, Ч5 §15).
5. **Черновик → предпросмотр → атомарная публикация.** Посетитель видит только опубликованное и всегда согласованную версию (Ч3 §49-50, Ч8 §14, Ч10 §11).
6. **Заявка сначала в БД, потом уведомления.** Сбой мессенджера или почты не теряет заявку (Ч6 §13, Ч8 §17).
7. **Секреты только на сервере**, RLS или эквивалент на всех приватных данных (Ч8 §4-5).
8. **Mobile first** и доступность, `prefers-reduced-motion` (Ч2 §32-33, Ч9 §17-18).
9. **Приоритеты при нехватке объёма:** безопасность и данные → работоспособность → архитектура → удобство управления → UX → визуал → производительность → декор (START_HERE §7, Ч10 §26).

## 1. Общая концепция
- Учебный центр бьюти-профессий «АлтынНур» («золотой свет»), Туймазы, Республика Башкортостан; владелица и преподаватель Айгуль Алтынбаева. Аудитория: женщины, которые хотят освоить или расширить бьюти-профессию; география Туймазы, Октябрьский, Белебей, Бавлы (Ч1 §2).
- Задача: заявки на обучение. Образ серьёзного учебного центра, а не «сайта мастера».
- Сайт простой для посетителя, админка мощная для владелицы, без знания кода.
- Визуально: сдержанная роскошь, editorial, эстетика beauty-журналов, не шаблон и не «магазин косметики» (Ч9 §1).

## 2. Архитектура
- Модули: Public Website, Admin Panel, CMS, Design System, Content, Courses, Leads, Quiz Engine, Media, SEO Engine, Auth, API Layer, DB Layer, Notifications, Backups, Analytics (Ч10 §4). Раздельно UI, логика, БД, стили; без файлов на тысячи строк.
- Задел на будущее (не делать сейчас): онлайн-оплата, кабинет ученицы, расписание занятий, бронь мест, промокоды, рефералка, электронные сертификаты, блог, несколько преподавателей, роли (Ч1 §4.4, Ч7 §18).
- Схема БД в миграциях, воспроизводимая из файлов (Ч10 §5). Нормализованные сущности, JSON только для гибкого содержимого блоков (Ч5 §20).

  - Курсы: `courses`, `course_categories`, `course_modules`, `course_topics`, `course_batches` (наборы и расписание), `teachers`, `teacher_courses`.
  - Контент: `galleries`, `gallery_items`, `before_after_items`, `reviews`, `faqs`, `advantages`, `promotions`, `contacts`, `media`, `media_folders`, `content_versions`.
  - Лиды: `leads`, `lead_statuses`, `lead_notes`, `lead_status_history`, `lead_events`, `quiz_questions`, `quiz_answers`, `quiz_sessions`, `quiz_recommendations`, `consent_records`.
  - Система: `integrations`, `notification_settings`, `notification_queue`, `notification_logs`, `analytics_events`, `seo_settings`, `redirects`, `legal_documents`, `audit_logs`, `backups`, `admin_settings`.
- Для каждой: PK, FK, обязательные поля, типы, ограничения, индексы, права, правила удаления (без каскадного уничтожения связанных данных), created_at, updated_at, статус, порядок.
- Стек: см. OPEN_QUESTIONS №1-2. Требования к нему: реальная БД и файловое хранилище, серверная часть для секретов и проверок, серверный или пререндер HTML для SEO, хранение ПДн по 152-ФЗ, низкая стоимость.

## 4. Структура страниц
- Система страниц, у каждой свой набор блоков, URL, SEO, статус; порядок в меню меняется без смены URL; главная не закреплена (Ч3 §51).
- Старт: Главная, Все курсы `/courses/`, курс `/courses/<slug>`, Преподаватель `/teacher/`, Галерея `/gallery/`, Контакты `/contacts/`, Политика `/privacy-policy/`, 404 (Ч7 §2.1).
- Страница курса из одного шаблона, только разделы с данными, похожие курсы, форма записи с подставленным курсом (Ч2 §17, Ч5 §3.3).
- Инфо-страницы собираются из тех же блоков (Ч5 §14). Блог и городские страницы: только задел (Ч7 §5, §18).

## 5. Административная панель
- Вход: малозаметная ссылка «Админка» → страница входа (email, пароль, показать пароль, восстановление, понятные ошибки, загрузка). Скрытый URL не защита (Ч3 §39).
- Dashboard: заявки всего и новые, опубликованные курсы, активные наборы, скрытые блоки, черновики; последние действия; быстрые действия; состояние сайта (Ч3 §40).
- Меню по группам: Главное, Контент, Заявки, Дизайн, Медиа, Система; сворачивание, мобильный вид (Ч3 §41, Ч10 §7).
- Центр предупреждений (Критично, Важно, Рекомендация) с переходом в редактор; критичное (сломанная форма, нет согласия) блокирует публикацию функции (Ч3 §54). Видимые только админу пометки о незаполненном (Ч2 §35).
- Глобальный поиск по курсам, полям, страницам, блокам, отзывам, фото, настройкам (Ч3 §55, Ч5 §18). Массовые действия с подтверждением.
- UX: язык без терминов, подсказки, крупные зоны нажатия, подтверждения, автосохранение, честный индикатор «Сохранено» (Ч3 §56-58).
- **Полноценная мобильная админка**: выдвижное меню, полноэкранные редакторы, кнопки «Выше/Ниже» вместо drag & drop (Ч3 §57).

## 6. Визуальный редактор
- Два режима на одних данных: структурный (список блоков) и визуальный (страница с выбором элементов) (Ч3 §42, Ч10 §9).
- Inline: «Редактировать сайт» → рамка при наведении → клик по тексту, фото, кнопке, карточке, фону → нужный редактор; вкладки Контент / Изображение / Дизайн / Ссылка / Дополнительно; работа в черновике; посетители инструментов не видят (Ч4 §22, Ч5 §17, Ч10 §10).
- Предпросмотр: страница, блок, телефон, планшет, ПК; разделённый экран и полный экран; реальные данные; защищён от посторонних (Ч3 §49, Ч4 §18).

## 7. Конструктор блоков
- Единая модель блока: ID, название, тип, видимость, позиция, содержимое, настройки вида и адаптива, дата изменения (Ч1 §12).
- Действия: добавить из библиотеки (Основные, Коммерческие, Информационные, Визуальные; поиск), редактировать (вкладки Содержимое, Медиа, Вид, Расположение, Адаптив, Дополнительно, SEO), скрыть (сохраняя всё), дублировать (новый ID, независимая копия), удалить (подтверждение, отмена через историю, медиа не удалять), drag & drop с индикатором (Ч3 §43-47).
- **Порядок реальный: если первым стоят контакты, страница начинается с них** (Ч10 §8).
- Шаблоны вида блока при тех же данных (отзывы, каталог, преимущества) (Ч3 §52). Видимость отдельных элементов (Ч3 §53).

## 8. Управление контентом
- Подразделы: курсы, категории, программы, преподаватели, расписание, галерея, работы учениц, отзывы, преимущества, FAQ, акции и бонусы, инфо-страницы, контакты, медиатека; единые действия (создать, редактировать, опубликовать, скрыть, архивировать, удалить, восстановить из корзины) (Ч5 §2).
- Преподаватели: Айгуль, архитектура под нескольких; только подтверждённые регалии; галерея документов JPG, PNG, WebP, PDF (Ч2 §20, Ч5 §7).
- Галереи, фото с alt, автором, курсом, признаком «ученица/преподаватель»; до/после только из реальных пар; **проверка согласия людей на фото перед публикацией** (Ч2 §21, Ч5 §9).
- Отзывы: текст, скриншот, видео, внешний источник; статусы Черновик, На проверке, Опубликован, Скрыт; выбор для главной (Ч2 §23, Ч5 §10).
- FAQ общие и курсовые, акции с автоокончанием по сроку, преимущества и бонусы без фиксированного количества (Ч5 §11-13).
- Контакты централизованно с переключателями показа (Ч5 §15).
- Медиатека: папки, мультизагрузка, поиск, сетка и список, повторное использование, предупреждение и замена при удалении используемого файла; автооптимизация (WebP, AVIF при возможности, миниатюры, `srcset`/`sizes`); видео с постером (Ч5 §16).
- История и откат ключевых полей (например, прошлые цены) (Ч5 §19).

## 9. Курсы и расписание
- Редактор курса из 8 вкладок: Основное, Стоимость, Параметры, Результаты, Программа (модули → темы без лимита, копирование программы между курсами), Наборы, Медиа, SEO (Ч5 §3, §6).
- Статусы курса: Черновик, Опубликован, Набор открыт, Набор закрыт, Архивный (Ч1 §11); статусы публикации: Черновик, Опубликован, Скрыт, Архив (Ч5 §19). Свести в одну модель: статус публикации + отдельный флаг или статус набора.
- Категории с вложенностью, удаление без потери курсов (Ч5 §5).
- Наборы: несколько на курс, даты, время, дни, формат, места, статусы (Скоро набор, Открыт, Мест мало, Заполнен, Завершён, Дата уточняется); список и календарь; места не считать автоматически; без искусственного дефицита (Ч2 §24, Ч5 §8).
- Сид-данные 7 курсов с предварительными ценами 10 000 / 20 000 / 15 000 / 20 000 / 8 000 / 3 000 / 8 500 ₽, остальные поля пусты (Ч5 §4). Точные названия: OPEN_QUESTIONS.
- Цена: старая цена только при реальной акции, «Стоимость уточняйте», скрытие цены, оплата частями не называется рассрочкой (Ч2 §26, Ч5 §3.2).

## 10. Квиз и заявки
- Формы (консультация, запись на курс, подбор, обратный звонок) через одну систему; поля настраиваются; курс подставляется («Вы оставляете заявку на курс: …»); при ошибке форма не очищается; успех «Спасибо! Ваша заявка отправлена. Мы свяжемся с вами по указанному номеру» (Ч2 §31, Ч6 §2-3).
- Квиз из 3 вопросов (опыт, цель, формат) с вариантами из Ч6 §4; движок без лимита вопросов; рекомендации из реальных курсов по их характеристикам; при неясности консультация; **результат до запроса телефона**, отказ не блокирует; заявка после квиза несёт ответы, рекомендации, выбранный курс, дату, источник (Ч6 §4-6). Квиз не обязателен для просмотра цен (Ч11 §6).
- Квиз редактируется в админке, включая привязку ответов к категориям и курсам.

## 11. CRM
- Список и Kanban с переключением; поиск, фильтры, сортировка, счётчики, новые сверху (Ч6 §7-8).
- 10 стартовых статусов (Новая … Закрыта) плюс свои с цветом; история статусов и действий не стирается; внутренние заметки; быстрые действия (позвонить, WhatsApp с заготовкой, Telegram, копировать номер) без автоотправки (Ч6 §7).
- Аналитика заявок и конверсий по единой методике, только реальные числа; экспорт CSV (XLSX по возможности) с учётом прав (Ч6 §14, §18).
- Удобная мобильная CRM на карточках (Ч6 §23).

## 12. Интеграции
- WhatsApp: контекстные шаблоны сообщений, редактируемые; переход не считается заявкой (Ч6 §10).
- Telegram: ссылка; уведомления через бота, токен на сервере, тестовое сообщение, отключаемо, минимум ПДн (Ч6 §9.2, §11).
- Email через серверную интеграцию (Ч6 §9.3).
- Очередь уведомлений с ограниченными повторами и статусом доставки (Ч6 §9.4).
- Realtime-обновление списка заявок в открытой админке (Ч6 §9.1); если стек не даёт realtime, допустим периодический опрос.
- Яндекс Метрика: ID в админке, 11 событий, успех только после подтверждения сервера, без дублей; GA по необходимости (Ч6 §16).
- У каждой интеграции: настройки, проверка, статус, логи, отключение; не показывать «подключено», если не работает (Ч10 §13).
- UTM и источники сохраняются с заявкой без избыточного отслеживания (Ч6 §15).

## 13. SEO
- ЧПУ, уникальные Title и Description, один H1, canonical, динамический sitemap, robots (админка и черновики закрыты), настоящий 404, 301 при смене URL и управление редиректами без циклов (Ч7 §2, §14-15).
- SEO-поля у курсов и страниц с автопредложением; SEO-раздел с предпросмотром сниппета и подсказками (Ч7 §3, §11).
- Локальное SEO по Туймазам и соседним городам без переспама; городские страницы только с реальной информацией (Ч7 §4-5).
- Schema.org: EducationalOrganization, Course, Person, BreadcrumbList, WebSite, WebPage, FAQPage по правилам; без выдуманных рейтингов и адреса (Ч7 §7).
- Open Graph и Twitter Cards с выбором картинки; alt-тексты с проверкой; хлебные крошки; верификация Вебмастера и Search Console с инструкцией (Ч7 §8, §12-13, §16).

## 14. Безопасность
- Проверенная система авторизации, лимит попыток, сессии, выход, смена и восстановление пароля, серверная проверка прав на каждом запросе (Ч3 §39, Ч8 §3, §18).
- Роли с заделом: Владелец, Администратор, Редактор, Менеджер заявок, Наблюдатель (Ч3 §39.3, Ч8 §3.2; свести в один список).
- Разделение публичного и приватного на уровне API: приватное никогда не уходит в браузер (Ч8 §4).
- `.env.example`, `.env` в `.gitignore`, проверка утечек перед публикацией (Ч8 §5).
- Формы: серверная валидация, rate limit, honeypot, идемпотентность, лимит длины, CAPTCHA по необходимости (Ч6 §12, Ч8 §6).
- XSS: санитайзер с белым списком для форматированного текста, без произвольного HTML, CSS, JS в полях дизайна, SEO, импорта тем (Ч4 §21, §24; Ч7 §19; Ч8 §7).
- Загрузки: проверка MIME, расширения, реального формата, размера; без исполняемых; приватные файлы закрыты (Ч8 §8).
- Журнал действий, корзина, двойное подтверждение опасных операций, мониторинг состояния, ошибки без утечек, HTTPS (Ч8 §12-19).
- Резервные копии на серверной стороне, раздел с историей и восстановлением с контрольной копией (Ч8 §11).

## 15. Юридические требования
- Редактируемые документы: политика обработки ПДн, согласие, условия использования (если нужны), согласие на рассылки (если будут) (Ч8 §9).
- Политика: оператор, данные, цели, основания, обработка, место хранения, передачи, сроки, отзыв, контакт. Реквизиты не выдумывать, явные заглушки, не публиковать как готовую с пустыми обязательными полями.
- Чекбокс не отмечен заранее, без него нет отправки; с заявкой хранятся дата, время, версия и ID документа (Ч6 §20, Ч8 §9.2). Рекламное согласие отдельно.
- **152-ФЗ: локализация ПДн российских граждан, передачи третьим сервисам, трансграничная передача** (Ч8 §9.4, Ч10 §3). Тексты проверяет юрист, мы готовим механизм.
- Хранение заявок: архив, удаление, экспорт; автоудаление только по утверждённому правилу (Ч8 §10).

## 16. Дизайн-система
- Design tokens на CSS-переменных, 4 уровня наследования Элемент > Блок > Страница > Тема, видимость «своё/унаследованное», сброс (Ч4 §2).
- Тема «Ночное золото»: #0E0E0E (60% фон), #1C1C1C и #F7F3EA/#E8D9B5 (30% поверхности и светлые секции), #C9A45C (10%: CTA, цены, активные состояния). Совпадает с нашим правилом «1+2+3» (Ч4 §19, Ч9 §2).
- Шрифты: Playfair Display + Ysabeau Office или Finlandica, кириллица, не Inter; адаптивная шкала через `clamp()` (Hero, H1-H4, Body L/M/S, Caption, Label, Button, Price) (Ч4 §5, Ч9 §5).
- Раздел «Дизайн»: цвета с ролями и проверкой контраста, типографика, скругления, Liquid Glass (11 параметров, по компонентам, fallback), карточки (9 стилей), кнопки (6 типов × 6 состояний), фоны (цвет, градиент, фото, видео), тени и границы, отступы и сетка по устройствам, изображения (фокальная точка), иконки (единый SVG-набор) (Ч4 §3-14).
- Темы: готовые и свои, экспорт и импорт JSON с валидацией (Ч4 §19-21).
- Undo, redo, история, откат дизайна (Ч4 §20).
- Композиция секций разная, не одинаковые карточки и сетки 3×3, без золотых градиентов, блёсток, корон (Ч4 §25, Ч9 §3, Ч11 §4).

## 17. Анимации
- Единая система: Fade, Slide, Scale, Blur, Stagger; заголовки по строкам; маски фото; лёгкий hover карточек; плавные аккордеоны, квиз, лайтбокс, до/после (с клавиатурой) (Ч9 §6-13).

- Раздел «Анимации»: вкл/выкл, интенсивность, скорость, типы, параллакс, карточки, кнопки, фото, задержки; пресеты Minimal, **Elegant (старт)**, Editorial, Dynamic (Ч9 §20). Это тот же раздел, что «Анимации» в Ч4 §15.
