# Часть 7. SEO, локальное продвижение, производительность

## Назначение
Корректная индексация (Яндекс, Google), страницы под направления, локальное SEO (Туймазы и соседние города), скорость, SEO-управление из админки, подготовка Метрики, GA, Вебмастера, Search Console, задел под блог. Позиции в выдаче не обещать.

## Техническая основа (§2)
- Человекопонятные латинские URL, уникальные Title и Description, правильная иерархия заголовков, canonical, sitemap.xml, robots.txt, корректные HTTP-статусы, страница 404, редиректы, Open Graph, Twitter Cards, Schema.org, мобильная индексация. Без дублей с разными URL.
- Не индексировать админку, технические страницы, черновики, предпросмотр.
- URL: `/`, `/courses/`, `/courses/brows`, `/courses/lashes`, `/courses/cosmetology`, `/teacher/`, `/gallery/`, `/contacts/`, `/privacy-policy/`. Новые URL генерируются из названия, редактируемы.
- Смена URL опубликованной страницы: старый сохраняется, **301** на новый, без циклов, проверка.
- Sitemap динамический: главная, опубликованные курсы, инфо-страницы, преподаватели, прочие индексируемые. Без админки, черновиков, скрытых, технических, дублей, noindex. Обновляется при публикации.
- robots.txt закрывает админ- и технические маршруты, не блокирует CSS, JS и картинки. Не способ скрыть конфиденциальное (это защищает серверная авторизация).
- Canonical на каждой индексируемой странице, особенно с параметрами фильтров и сортировки. Не ставить canonical на главную для всех страниц.

## SEO курсов (§3)
Поля: SEO Title, Meta Description, URL, Canonical, OG-изображение, индексация, основная поисковая тема, доп. фразы. Если пусто, автопредложение из названия и описания (редактируемое). Уникальные Title и Description, каждая страница под свой запрос, без неподтверждённых обещаний.

## Локальное SEO (§4-5)
- Основной город Туймазы (РБ), также Октябрьский, Белебей, Бавлы, ближайшие пункты.
- Направления для исследования запросов (не утверждения о программах): курсы бровиста в Туймазах, обучение на бровиста в Туймазах, курсы наращивания ресниц в Туймазах, обучение ламинированию ресниц, курсы косметик-эстетиста, обучение бьюти-профессиям, курсы маникюра и педикюра, обучение мастеров красоты, курсы для начинающих мастеров, обучение бьюти-профессиям в Октябрьском и Белебее.
- Ключи естественно по главной, курсам, инфо-страницам, FAQ, заголовкам, описаниям, метаданным. Без переспама.
- Локальные страницы городов: только архитектурная возможность. Создавать только с реальной информацией (где центр, как добраться, курсы, организация, можно ли приехать из соседнего города, наборы, запись). Без десятков одинаковых страниц, без выдуманных маршрутов и времени в пути.

## Заголовки (§6)
Один H1 на страницу, H2 разделы, H3 подразделы, H4 при необходимости. Уровень по семантике, размер через CSS. Все заголовки редактируются в CMS.

## Schema.org (§7)
- Типы по реальной деятельности: EducationalOrganization, Organization, Course, Person, BreadcrumbList, WebSite, WebPage, FAQPage (если применимо по правилам поисковиков).
- Не указывать несуществующие рейтинги, отзывы, адреса, телефоны, лицензии, аккредитации, цены, даты.
- Организация: АлтынНур, Туймазы, Республика Башкортостан, Россия, Айгуль Алтынбаева, VK https://vk.ru/azolotaya82, телефон +7 927 636-32-30. Адрес не добавлять до подтверждения.
- Курсы: только существующие поля, валидный JSON-LD, без скрытого текста, не совпадающего с видимым содержимым.

## Open Graph (§8)
og:title, og:description, og:image, og:url, og:type, twitter:card, twitter:title, twitter:description, twitter:image. Выбор изображения превью в админке, по умолчанию общая обложка сайта, правильные пропорции и оптимизация.

## Скорость, Core Web Vitals (§9)
- Быстро на мобильных и плохом интернете. Оптимизировать HTML, CSS, JS, фото, шрифты, видео, анимации, запросы к БД. Цели по LCP, INP, CLS без обещаний идеала.
- Фото: WebP, AVIF, адаптивные, lazy loading, правильные размеры, сжатие, preload только важных. Галерею не грузить целиком. Hero-фото без lazy, если это вредит LCP.
- Шрифты: только нужные начертания, WOFF2, `font-display: swap`, проверка кириллицы.
- JS: без тяжёлых библиотек, второстепенное по требованию, не блокировать основной контент.
- Стабильность макета: размеры фото и резерв места; проверить hero, карточки, галереи, шрифты, формы, попапы.

## Мобильная оптимизация (§10)
Мобильная версия основная. Проверить ширину, шрифты, высоту кнопок, отступы, читаемость, скорость, формы, галереи, навигацию, фото, квиз, страницы курсов. Без горизонтальной прокрутки, удобные зоны нажатия.

## SEO-раздел в админке (§11)
Общие настройки, SEO главной, курсов, инфо-страниц, Meta Title, Description, OG, Canonical, индексация, alt. Предпросмотр сниппета (без обещаний, что поисковик покажет именно его).
Подсказки: нет Title, нет Description, длинный заголовок, короткое описание, нет H1, нет основного фото, нет alt у важного фото, дубль Title, страница закрыта от индексации, нет canonical. Делить на критичные и рекомендации, не блокировать публикацию каждым предупреждением.

## Alt-тексты (§12)
Для значимых фото, описывают реальное содержимое (пример: «Практическое занятие по оформлению бровей в учебном центре АлтынНур»), не набор ключей. Декоративные с пустым alt. Проверка отсутствующих alt.

## Хлебные крошки (§13)
Для вложенных страниц (Главная → Курсы → Обучение бровям): кликабельные, адаптивные, по реальной структуре, с BreadcrumbList. Не там, где не нужны.

## 404 (§14)
Понятное сообщение, кнопка на главную, ссылка на каталог, переход к контактам. Реальный HTTP-статус 404, без технической ошибки.

## Редиректы (§15)
Админка: добавить, изменить, удалить, список, проверка цели. При удалении опубликованной страницы предложить редирект на подходящую (не всё на главную). Без циклов и цепочек.

## Вебмастер и Search Console (§16)
Возможность добавить код подтверждения или другой способ верификации, sitemap для отправки, инструкция для владелицы в админке. Секреты не во frontend. Не заявлять об индексации без проверки.

## Изображения и галереи (§17)
Понятные имена файлов, alt, подписи, размеры, индексация только подходящих публичных фото, корректные URL, OG для индексируемых галерей. Без отдельной страницы на каждое фото.

## Блог (задел, §18)
Темы на будущее: советы начинающим мастерам, о профессиях, разборы направлений, о процедурах, выбор курса, ответы на вопросы, реальные истории. Статей сейчас не создавать. Поля статьи: заголовок, текст, обложка, категория, дата, автор, SEO, статус, ЧПУ. Без выдуманных историй.

## Безопасность SEO (§19)
Никакого JS и опасного HTML через SEO-поля. Валидация URL, canonical, изображений, мета, JSON-LD, редиректов. Нет открытых редиректов на внешние сайты. SEO-данные публичны для роботов, админ-данные закрыты.

## Проверка перед запуском (§20)
URL, Title, Description, H1, canonical, sitemap, robots, статусы, редиректы, структурированные данные, OG, alt, мобильная версия, скорость, отсутствие дублей и технических страниц в индексе. Инструменты: Google Rich Results Test, Schema Markup Validator, PageSpeed Insights, Яндекс Вебмастер после подключения. Неподключённое отмечать отдельно, результаты не имитировать.

## Критерии проверки (§21, 25 пунктов)
URL; свой Title и Description у каждой страницы; SEO курсов; автогенерация sitemap; robots; canonical; 301; 404 с кодом; OG; Schema.org; крошки; alt; SEO-раздел; сниппеты; предупреждения; админка noindex; черновики вне sitemap; оптимизированные фото; мобильный адаптив; нет критических проблем загрузки; готовность Вебмастера и Search Console; SEO в БД; никаких выдуманных данных.
Отчёт: что сделано, какие функции работают, что подключено, что заполнить, что сделать владелице перед продвижением.

## Технический вывод
Мета-теги, JSON-LD, 301, настоящий 404 и динамический sitemap не работают, если страницы собираются в браузере из Supabase. Нужен пререндер (сборка HTML при публикации) или серверный рендер. Влияет на выбор стека и хостинга (см. OPEN_QUESTIONS).
