ЧАСТЬ 5. ПОЛНОЦЕННАЯ СИСТЕМА УПРАВЛЕНИЯ КОНТЕНТОМ

1. Главная задача

Создай полноценную CMS для управления всеми информационными материалами сайта учебного центра «АлтынНур».

Владелица должна самостоятельно управлять содержимым сайта через административную панель.

Ей не нужно обращаться к разработчику, чтобы:

* Добавить новый курс.
* Удалить курс.
* Изменить название курса.
* Изменить стоимость.
* Изменить описание.
* Изменить программу обучения.
* Добавить новые уроки или темы.
* Изменить длительность обучения.
* Добавить дату ближайшего набора.
* Изменить количество мест.
* Добавить информацию о преподавателе.
* Загрузить фотографии.
* Добавить фотографии работ учениц.
* Создать галерею.
* Добавить отзыв.
* Изменить FAQ.
* Добавить акцию.
* Изменить контактные данные.
* Добавить новый информационный материал.

Все данные должны храниться в базе данных и загружаться на публичный сайт динамически.

Не создавай систему, в которой данные просто меняются в интерфейсе админки, но остаются захардкоженными в HTML или JavaScript.

Каждая функция должна работать с реальными данными.

2. Общая структура раздела «Контент»

В административной панели создай отдельный раздел управления содержимым.

Предусмотри следующие подразделы:

1. Курсы.
2. Категории курсов.
3. Программы обучения.
4. Преподаватели.
5. Расписание и наборы.
6. Галерея работ.
7. Работы учениц.
8. Отзывы.
9. Преимущества.
10. FAQ.
11. Акции и бонусы.
12. Информационные страницы.
13. Контакты.
14. Медиатека.

Каждый подраздел должен иметь понятный интерфейс, поиск, фильтрацию и возможность добавления новых записей.

Предусмотри единообразную логику:

* Создать.
* Открыть.
* Редактировать.
* Сохранить.
* Опубликовать.
* Скрыть.
* Архивировать.
* Удалить.
* Восстановить, если предусмотрена корзина.

Для удаления важных объектов используй подтверждение действия.

Не допускай случайного удаления большого количества данных.

3. Управление курсами

Это один из главных разделов всей административной панели.

Создай полноценный каталог курсов, в котором владелица сможет самостоятельно добавлять, редактировать и удалять программы обучения.

На публичном сайте курсы должны автоматически появляться в каталоге после публикации.

3.1. Список курсов в админке

Отображай курсы в виде удобной таблицы или карточек.

Для каждого курса показывай:

* Название.
* Категорию.
* Обложку.
* Стоимость.
* Статус.
* Длительность.
* Ближайшую дату набора.
* Количество доступных мест, если оно указано.
* Дату последнего изменения.

Добавь фильтры:

* Все курсы.
* Опубликованные.
* Черновики.
* Скрытые.
* Архивные.
* По категориям.
* По стоимости.
* По дате ближайшего набора.

Добавь поиск по названию.

Предусмотри сортировку по названию, цене, дате создания и дате обновления.

3.2. Создание курса

При нажатии «Добавить курс» открывается полноценный редактор.

Раздели его на понятные вкладки.

Вкладка 1. Основная информация

Поля:

* Название курса.
* Короткое описание.
* Полное описание.
* Категория.
* Подкатегория.
* Обложка.
* Дополнительные фотографии.
* Иконка или декоративный элемент.
* Статус публикации.
* Порядок отображения.
* Отметка «Популярный курс».
* Отметка «Новинка».
* Отметка «Рекомендуем».
* Отметка «Набор открыт».

Все отметки должны быть необязательными.

Вкладка 2. Стоимость

Поля:

* Основная цена.
* Старая цена, если есть реальная акция.
* Текст рядом с ценой.
* Возможность указать «Стоимость уточняйте».
* Возможность скрыть цену.
* Возможность указать рассрочку.
* Условия оплаты.
* Дополнительные платежи, если они есть.

Не показывай зачеркнутую старую цену, если владелица ее не указала.

Не создавай автоматические скидки и фиктивные акции.

Вкладка 3. Параметры обучения

Поля:

* Длительность.
* Количество учебных часов.
* Формат обучения.
* Индивидуально или в группе.
* Количество учеников в группе.
* Уровень подготовки.
* Наличие практики.
* Наличие моделей.
* Наличие материалов.
* Наличие оборудования.
* Наличие сертификата.
* Поддержка после обучения.
* Возрастные или иные ограничения, если они существуют.

Для неизвестных значений разреши оставить поле пустым.

Пустые значения не должны превращаться в выдуманные характеристики на публичном сайте.

Вкладка 4. Результаты обучения

Позволи добавлять список результатов.

Например:

* Какие навыки получит ученик.
* Какие процедуры сможет выполнять.
* Какие техники освоит.
* Какие инструменты научится использовать.
* Какие знания получит.

Каждый пункт должен добавляться, удаляться и перемещаться вверх или вниз.

Вкладка 5. Программа курса

Создай отдельный конструктор программы обучения.

Владелица должна иметь возможность создавать разделы и добавлять в них темы.

Например:

Модуль 1. Теоретическая подготовка.

* Тема 1.
* Тема 2.
* Тема 3.

Модуль 2. Практика.

* Тема 1.
* Тема 2.

Для каждого модуля и темы можно указать:

* Название.
* Описание.
* Продолжительность.
* Порядок.
* Дополнительные материалы.
* Изображение, если необходимо.

Количество модулей и тем не должно быть ограничено жестко заданным числом.

Нужно поддержать добавление, удаление, дублирование и изменение порядка.

Вкладка 6. Даты и наборы

Позволи привязывать к курсу несколько наборов.

Для каждого набора:

* Дата начала.
* Дата окончания, если известна.
* Время занятий.
* Дни недели.
* Формат.
* Количество мест.
* Свободные места, если владелица ведет этот учет.
* Статус набора.
* Комментарий.

Статусы:

* Скоро набор.
* Открыт набор.
* Мест мало.
* Набор заполнен.
* Набор завершен.
* Дата уточняется.

Не рассчитывай автоматически количество оставшихся мест, если нет надежного источника данных.

Если дата неизвестна, можно использовать формулировку «Даты уточняются».

Вкладка 7. Фотографии и материалы

Позволи прикреплять к курсу:

* Главное изображение.
* Дополнительные фотографии.
* Фотографии процесса.
* Примеры работ.
* Фотографии сертификатов, если они существуют.
* Видео.
* Документы и материалы для скачивания, если это необходимо.

Все изображения должны выбираться из общей медиатеки или загружаться прямо из редактора курса.

Вкладка 8. SEO

Поля:

* SEO-заголовок.
* Meta Description.
* ЧПУ (slug).
* Ключевая фраза.
* Open Graph изображение.
* Индексация страницы.
* Canonical URL.

Создавай понятные адреса страниц.

Например:

/courses/brows

/courses/lashes

/courses/cosmetology

Slug должен редактироваться, но при изменении уже опубликованного адреса желательно создавать перенаправление со старого URL на новый.

3.3. Публичная страница курса

Для каждого курса автоматически создавай отдельную страницу на основе единого гибкого шаблона.

Страница должна содержать только те разделы, для которых есть данные.

Предусмотри:

* Обложку.
* Название.
* Краткое описание.
* Стоимость.
* Основные характеристики.
* Для кого предназначен курс.
* Чему научится ученик.
* Программу обучения.
* Практическую часть.
* Информацию о преподавателе.
* Фотографии.
* Ближайшие наборы.
* Условия оплаты.
* Ответы на вопросы.
* Форму записи.
* Похожие курсы.

Не показывай пустые разделы.

Если для конкретного курса нет информации о сертификате, не нужно автоматически писать, что сертификат выдается.

Каждая страница должна быть адаптивной и иметь собственные SEO-настройки.

Создай первоначальные записи курсов на основании предоставленного брифа.

Это предварительные данные, которые необходимо сделать редактируемыми.

Не воспринимай указанные цены и характеристики как окончательно подтвержденные.

5. Управление категориями курсов

Создай самостоятельный раздел категорий.

Владелица должна иметь возможность:

* Добавлять категории.
* Редактировать категории.
* Удалять категории.
* Менять название.
* Добавлять описание.
* Добавлять изображение.
* Менять порядок.
* Скрывать категорию.
* Привязывать курсы к категориям.

Категории могут использоваться для фильтрации каталога.

Предусмотри возможность создавать вложенные категории, если это потребуется в будущем.

При удалении категории не удаляй автоматически все связанные курсы.

Предложи перенести их в другую категорию или оставить без категории.

6. Управление программами обучения

Хотя программа курса уже предусмотрена в редакторе самого курса, создай универсальную архитектуру для ее хранения и управления.

Программа должна состоять из отдельных модулей и тем.

Требования:

* Неограниченное количество модулей.
* Неограниченное количество тем в модуле.
* Изменение порядка перетаскиванием.
* Дублирование модулей.
* Дублирование тем.
* Скрытие отдельных пунктов.
* Редактирование описаний.
* Добавление изображений.
* Возможность копировать программу из одного курса в другой.

Если программа курса содержит большое количество тем, на публичной странице сделай удобное раскрывающееся представление.

Не показывай всю программу огромной сплошной стеной текста.

7. Управление преподавателями

Создай раздел «Преподаватели».

На старте проекта предусмотрен один преподаватель:

Айгуль Алтынбаева.

Однако архитектура должна поддерживать добавление других преподавателей в будущем.

Для каждого преподавателя предусмотрены поля:

* Имя и фамилия.
* Должность.
* Краткая биография.
* Подробная биография.
* Фотография.
* Специализация.
* Опыт работы, если подтвержден.
* Образование, если подтверждено.
* Сертификаты и документы.
* Пройденные обучения.
* Достижения.
* Социальные сети.
* Контактные ссылки.
* Привязанные курсы.
* Порядок отображения.
* Статус публикации.

Не создавай вымышленные регалии, стаж, образование и профессиональные достижения.

Владелица должна самостоятельно добавлять и удалять информацию.

Предусмотри отдельную публичную страницу преподавателя, если в дальнейшем появится несколько преподавателей.

8. Расписание и управление наборами

Создай самостоятельный раздел «Расписание и наборы».

Он должен быть связан с курсами, но не зависеть от них полностью.

Один курс может иметь несколько наборов.

Один набор может иметь собственное расписание.

Добавь два режима отображения:

1. Список наборов.
2. Календарь.

В списке показывай:

* Название курса.
* Дату начала.
* Время.
* Формат.
* Статус.
* Количество мест, если указано.

В календаре показывай даты занятий и начала наборов.

Предусмотри фильтры по курсам и статусам.

Добавь возможность быстро создать новый набор прямо из карточки курса.

При изменении даты или статуса информация должна обновляться на публичной странице курса и в блоке ближайших наборов.

Если даты нет, не придумывай ее автоматически.

9. Управление галереей и работами учениц

Создай два взаимосвязанных, но самостоятельных раздела:

* Галерея.
* Работы учениц.

9.1. Галерея

Владелица должна иметь возможность создавать несколько галерей.

Например:

* Работы по бровям.
* Наращивание ресниц.
* Ламинирование.
* Маникюр.
* Педикюр.
* Уходовые процедуры.
* Работы по волосам.
* Учебный процесс.

Это примеры категорий, а не утверждение, что все соответствующие фотографии уже существуют.

Для каждой галереи:

* Название.
* Описание.
* Обложка.
* Список изображений.
* Порядок.
* Статус.
* Категория.

9.2. Управление фотографиями

Для каждого изображения:

* Файл.
* Название.
* Описание.
* Альтернативный текст.
* Категория.
* Дата загрузки.
* Автор или владелец материала, если известен.
* Привязанный курс.
* Привязанный преподаватель.
* Статус публикации.
* Порядок отображения.

Добавь возможность:

* Перетаскивать изображения.
* Выбирать сразу несколько изображений.
* Удалять несколько изображений.
* Перемещать фотографии между галереями.
* Менять обложку.
* Создавать подборки.

9.3. Фотографии «До / После»

Создай отдельный тип галереи для сравнения результатов «До / После».

Для каждой пары:

* Фото до.
* Фото после.
* Подпись.
* Описание процедуры.
* Категория.
* Привязанный курс, если применимо.

На публичной странице используй интерактивный ползунок сравнения изображений.

На телефоне управление должно быть удобным.

Не создавай фиктивные фотографии до и после.

Используй только реальные материалы, загруженные владельцем.

Перед публикацией фотографий людей предусмотрена проверка наличия необходимых согласий на использование изображений.

10. Управление отзывами

Создай отдельный раздел «Отзывы».

Для каждого отзыва:

* Имя автора.
* Текст.
* Фотография автора, если разрешена.
* Дата.
* Привязанный курс.
* Оценка, если она действительно получена.
* Источник отзыва.
* Ссылка на оригинал, если доступна.
* Статус публикации.
* Порядок отображения.

Предусмотри возможность добавлять отзывы вручную.

Добавь возможность прикреплять скриншоты отзывов как изображения.

Если владелица добавляет отзыв в виде скриншота, на сайте должна быть возможность показать его как изображение.

Не создавай вымышленные отзывы, имена и оценки.

Не генерируй автоматически положительные отзывы.

Предусмотри статусы:
