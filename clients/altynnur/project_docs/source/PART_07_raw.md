ЧАСТЬ 7. SEO, ЛОКАЛЬНОЕ ПРОДВИЖЕНИЕ И ТЕХНИЧЕСКАЯ ОПТИМИЗАЦИЯ

1. Главная задача

Подготовь сайт учебного центра «АлтынНур» к полноценному продвижению в поисковых системах.

Основные цели:

1. Обеспечить корректную индексацию сайта.
2. Сделать страницы понятными для Яндекса и Google.
3. Подготовить отдельные страницы под направления обучения.
4. Улучшить видимость сайта по локальным поисковым запросам.
5. Обеспечить высокую скорость загрузки.
6. Сделать структуру сайта удобной для пользователей и поисковых роботов.
7. Реализовать управление SEO через административную панель.
8. Подготовить сайт к подключению Яндекс Метрики и Google Analytics, если это потребуется.
9. Предусмотреть техническую основу для дальнейшего продвижения и публикации полезных материалов.

Не обещай конкретные позиции в поисковой выдаче.

SEO-инфраструктура должна быть технически качественной, но реальные позиции будут зависеть от конкуренции, качества материалов, ссылок, поведения пользователей и других факторов.

2. Техническая SEO-архитектура

Обеспечь корректную индексацию всех публичных страниц.

Предусмотри:

* Человекопонятные URL.
* Уникальные Title.
* Уникальные Description.
* Корректную иерархию заголовков.
* Canonical URL.
* Sitemap.xml.
* Robots.txt.
* Корректные HTTP-статусы.
* Страницу 404.
* Редиректы.
* Open Graph.
* Twitter Cards.
* Микроразметку Schema.org.
* Корректную индексацию мобильной версии.

Не допускай появления нескольких одинаковых страниц с разными URL без необходимости.

Не индексируй административную панель, технические страницы, черновики и страницы предпросмотра.

2.1. Человекопонятные адреса

Используй короткие URL на латинице.

Примеры:

/
/courses/
/courses/brows
/courses/lashes
/courses/cosmetology
/teacher/
/gallery/
/contacts/
/privacy-policy/

Для новых страниц адрес должен формироваться автоматически из названия, но оставаться редактируемым в админке.

При изменении URL опубликованной страницы:

* Сохраняй старый адрес.
* Создавай 301-редирект на новый.
* Не допускай циклических редиректов.
* Проверяй корректность перенаправления.

2.2. Sitemap.xml

Создай динамическую XML-карту сайта.

В нее должны автоматически попадать:

* Главная.
* Опубликованные курсы.
* Опубликованные информационные страницы.
* Страницы преподавателей, если они опубликованы.
* Другие разрешенные для индексации страницы.

Не включай:

* Админку.
* Черновики.
* Скрытые страницы.
* Технические маршруты.
* Дубли страниц.
* Страницы с запретом индексации.

При публикации новой страницы карта сайта должна обновляться.

2.3. Robots.txt

Настрой корректный robots.txt.

Закрой от индексации административные маршруты и технические разделы.

Не блокируй случайно публичные CSS, JavaScript и изображения, необходимые поисковым роботам для понимания страницы.

Не используй robots.txt как единственный способ скрыть конфиденциальную информацию.

Конфиденциальные данные должны быть защищены авторизацией на сервере.

2.4. Canonical

Для каждой индексируемой страницы указывай корректный canonical URL.

Это особенно важно для страниц с параметрами фильтрации, сортировки и другими вариантами URL.

Не допускай случайного указания canonical на главную для всех страниц.

3. SEO для отдельных курсов

Каждый курс должен иметь отдельную SEO-настройку.

В редакторе курса из административной панели предусмотрены:

* SEO Title.
* Meta Description.
* URL.
* Canonical.
* Open Graph изображение.
* Разрешение индексации.
* Основная поисковая тема.
* Дополнительные поисковые фразы.

Если SEO-поля не заполнены, система может предложить автоматически сформированные варианты на основе названия и описания курса.

Однако владелица должна иметь возможность их изменить.

Не создавай одинаковые Title и Description для всех курсов.

Каждая страница должна отвечать на собственный поисковый запрос.

Например:

Страница обучения бровям должна раскрывать именно архитектуру и оформление бровей.

Страница обучения ресницам должна рассказывать о соответствующем направлении.

Страница косметик-эстетиста должна содержать только подтвержденную информацию о программе.

Не добавляй в SEO-тексты неподтвержденные обещания.

4. Локальное SEO

Это один из важнейших элементов продвижения.

Основной город учебного центра: Туймазы, Республика Башкортостан.

Дополнительно потенциальная аудитория может приезжать из:

* Октябрьского.
* Белебея.
* Бавлов.
* Других близлежащих населенных пунктов.

Подготовь сайт для локальных поисковых запросов.

Примеры поисковых направлений:

* Курсы бровиста в Туймазах.
* Обучение на бровиста в Туймазах.
* Курсы наращивания ресниц в Туймазах.
* Обучение ламинированию ресниц.
* Курсы косметик-эстетиста.
* Обучение бьюти-профессиям.
* Курсы маникюра и педикюра.
* Обучение мастеров красоты.
* Курсы для начинающих мастеров.
* Обучение бьюти-профессиям в Октябрьском и Белебее.

Это направления для дальнейшего исследования ключевых слов, а не готовые утверждения о том, что школа проводит все перечисленные программы.

Не размещай все ключевые слова в одном абзаце.

Распределяй их естественно:

* Главная страница.
* Страницы курсов.
* Информационные страницы.
* FAQ.
* Заголовки.
* Описания.
* Метаданные.

Не используй искусственное многократное повторение одного ключевого слова.

5. Локальные страницы по городам

Предусмотри архитектурную возможность создания дополнительных локальных страниц.

Например:

* Обучение бьюти-профессиям в Туймазах.
* Курсы для жителей Октябрьского.
* Обучение для жителей Белебея.

Но не создавай автоматически десятки почти одинаковых страниц.

Локальная страница должна содержать действительно полезную информацию:

* Где находится учебный центр.
* Как добраться.
* Какие курсы доступны.
* Как организовано обучение.
* Можно ли приехать из соседнего города.
* Какие есть ближайшие наборы.
* Как записаться.

Если фактической информации для отдельной страницы нет, лучше не создавать ее.

Не выдумывай адреса, время в пути, маршруты и географические преимущества.

6. Структура заголовков

Соблюдай правильную иерархию HTML-заголовков.

На каждой странице должен быть один основной H1, отражающий ее содержание.

Используй:

* H1 для главного заголовка.
* H2 для основных разделов.
* H3 для подразделов.
* H4 при необходимости.

Не выбирай уровень заголовка только ради визуального размера.

Размер должен определяться CSS, а структура - семантикой.

Не используй заголовки для обычного декоративного текста.

Все заголовки должны быть редактируемыми через CMS.

7. Schema.org и структурированные данные

Реализуй корректную микроразметку Schema.org.

Выбирай типы разметки исходя из реальной деятельности учебного центра.

Рассмотри:

* EducationalOrganization.
* Organization.
* Course.
* Person.
* BreadcrumbList.
* WebSite.
* WebPage.
* FAQPage, если применимость соответствует актуальным правилам поисковых систем.

Не добавляй неподтвержденные данные.

Не указывай несуществующие:

* Рейтинги.
* Отзывы.
* Адреса.
* Телефоны.
* Лицензии.
* Образовательные аккредитации.
* Цены.
* Даты обучения.

Не добавляй адрес до получения точной информации.

Не создавай фиктивные рейтинги и отзывы.

7.2. Разметка курсов

Для каждой опубликованной страницы курса добавляй соответствующую структурированную информацию.

Передавай только те поля, которые действительно существуют.

Проверяй корректность JSON-LD.

Не допускай ошибок синтаксиса.

Не добавляй скрытый текст в разметку, который не соответствует видимому содержимому страницы.

8. Open Graph и оформление ссылок

При отправке ссылки на сайт в социальных сетях и мессенджерах должно отображаться красивое превью.

Предусмотри:

* og:title.
* og:description.
* og:image.
* og:url.
* og:type.
* twitter:card.
* twitter:title.
* twitter:description.
* twitter:image.

В административной панели добавь возможность выбирать изображение для превью.

Если для конкретной страницы изображение не задано, используй общую обложку сайта.

Изображение должно иметь подходящие пропорции и оптимизированный размер.

Не используй случайные изображения.

9. Скорость загрузки и Core Web Vitals

Сделай производительность одним из приоритетов проекта.

Сайт должен быстро загружаться на мобильных устройствах, в том числе при нестабильном интернете.

Оптимизируй:

* HTML.
* CSS.
* JavaScript.
* Изображения.
* Шрифты.
* Видео.
* Анимации.
* Запросы к базе данных.

Ориентируйся на показатели Core Web Vitals:

* LCP.
* INP.
* CLS.

Не обещай идеальные значения заранее, но стремись к хорошим результатам на реальных устройствах.

9.1. Изображения

Используй:

* WebP.
* AVIF при поддержке.
* Адаптивные изображения.
* Lazy Loading.
* Правильные размеры.
* Сжатие.
* Предварительную загрузку действительно важных изображений.

Не загружай все фотографии галереи сразу.

Для первого экрана используй оптимизированное изображение нужного размера.

Не применяй lazy loading к главному изображению, если это ухудшает LCP.

9.2. Шрифты

Загружай только необходимые начертания.

Используй WOFF2, если это возможно.

Предусмотри font-display: swap.

Не загружай десятки ненужных вариантов одного шрифта.

Проверь корректное отображение кириллицы.

9.3. JavaScript

Не подключай тяжелые библиотеки без необходимости.

Загружай второстепенные компоненты по требованию.

Не блокируй отображение основного контента.

Анимации должны работать плавно и не перегружать телефон.

9.4. Стабильность макета

Задавай размеры изображений и резервируй место под элементы, которые загружаются позже.

Не допускай постоянного смещения контента после загрузки.

Особенно проверь:

* Hero.
* Карточки курсов.
* Галереи.
* Шрифты.
* Формы.
* Всплывающие элементы.

10. Мобильная оптимизация

Большинство посетителей, вероятно, будут заходить с телефона.

Поэтому мобильная версия должна быть полноценной, а не дополнительной адаптацией после разработки десктопа.

Проверь:

* Ширину контента.
* Размеры шрифтов.
* Высоту кнопок.
* Расстояния между элементами.
* Читаемость.
* Скорость загрузки.
* Корректность форм.
* Галереи.
* Навигацию.
* Отображение фотографий.
* Квиз.
* Страницы курсов.

Не допускай горизонтальной прокрутки.

Все интерактивные элементы должны иметь удобную область нажатия.

11. Локальные поисковые фразы и SEO-редактор

Создай в админке отдельный раздел SEO.

В нем владелица сможет редактировать:

* Общие настройки сайта.
* SEO главной страницы.
* SEO отдельных курсов.
* SEO информационных страниц.
* Meta Title.
* Meta Description.
* Open Graph.
* Canonical.
* Индексацию.
* Alt-тексты изображений.

Добавь визуальный предпросмотр поискового сниппета.

Показывай приблизительно, как заголовок и описание могут выглядеть в поисковой выдаче.

Не обещай, что поисковик обязательно покажет именно этот текст.

11.1. SEO-подсказки

Добавь автоматические рекомендации:

* Не заполнен Title.
* Не заполнен Description.
* Слишком длинный заголовок.
* Слишком короткое описание.
* Отсутствует H1.
* Нет основного изображения.
* Отсутствует Alt у важного изображения.
* Дублируется Title.
* Страница закрыта от индексации.
* Не задан Canonical.

Не блокируй публикацию из-за каждого предупреждения.

Разделяй критические ошибки и рекомендации.

12. Alt-тексты изображений

Предусмотри возможность добавлять альтернативные описания ко всем значимым изображениям.

Например:

«Практическое занятие по оформлению бровей в учебном центре АлтынНур».

Alt должен описывать реальное содержимое фотографии.

Не превращай Alt в набор поисковых слов.

Для декоративных изображений используй пустой alt, если это соответствует их назначению.

Добавь проверку отсутствующих Alt в SEO-разделе.

13. Хлебные крошки

Реализуй хлебные крошки для вложенных страниц.

Например:

Главная → Курсы → Обучение бровям.

Они должны:

* Показывать путь пользователя.
* Быть кликабельными.
* Адаптироваться под телефон.
* Соответствовать реальной структуре страниц.
* Поддерживать BreadcrumbList Schema.org.

Не показывай хлебные крошки на страницах, где они не нужны.

14. Страница 404

Создай красивую и функциональную страницу 404.

Если посетитель перешел по несуществующему адресу, покажи:

* Понятное сообщение.
* Кнопку на главную.
* Ссылку на каталог курсов.
* Возможность перейти к контактам.

Не показывай техническую ошибку сервера вместо пользовательской страницы.

При этом сервер должен возвращать корректный HTTP-статус 404.

15. Перенаправления и удаленные страницы

Создай управление редиректами.

В админке желательно предусмотреть возможность:

* Добавить редирект.
* Изменить редирект.
* Удалить редирект.
* Просмотреть список.
* Проверить целевой адрес.

При удалении опубликованной страницы предложи создать перенаправление на подходящую страницу.

Не перенаправляй все удаленные страницы автоматически на главную.

Избегай циклов и цепочек перенаправлений.

16. Подключение Яндекс Вебмастера и Google Search Console

Подготовь сайт к подключению:

* Яндекс Вебмастер.
* Google Search Console.

Предусмотри возможность добавить код подтверждения или другой поддерживаемый способ верификации.

Не размещай секретные ключи в открытом frontend-коде.

Подготовь sitemap.xml для отправки в поисковые системы.

Добавь понятную инструкцию в админке о том, как владелица сможет подключить сайт к поисковым сервисам.

Не заявляй, что сайт уже проиндексирован, пока это не проверено.

17. SEO для изображений и галерей

Фотографии работ могут быть важной частью привлечения посетителей.

Предусмотри:

* Понятные имена файлов.
* Alt.
* Подписи.
* Оптимизированные размеры.
* Индексацию только подходящих публичных изображений.
* Корректные URL.
* Open Graph для отдельных страниц галерей, если они индексируются.

Не создавай отдельные индексируемые страницы для каждого изображения без необходимости.

18. Контентная основа для дальнейшего продвижения

Предусмотри архитектуру для будущего раздела полезных материалов.

В дальнейшем владелица может публиковать:

* Советы начинающим мастерам.
* Материалы о бьюти-профессиях.
* Разборы направлений обучения.
* Информацию о процедурах.
* Советы по выбору курса.
* Ответы на частые вопросы.
* Истории обучения и практики, если они основаны на реальных событиях.

Пока не нужно автоматически создавать десятки статей.

Нужно предусмотреть техническую возможность добавить блог через CMS.

Для каждой статьи должны быть:

* Заголовок.
* Текст.
* Обложка.
* Категория.
* Дата публикации.
* Автор.
* SEO-настройки.
* Статус.
* ЧПУ.

Не создавай фиктивные истории учеников.

19. Безопасность SEO-функций

Не позволяй через SEO-поля внедрять произвольный JavaScript или опасный HTML.

Проверяй:

* URL.
* Canonical.
* Изображения.
* Meta-данные.
* JSON-LD.
* Перенаправления.

Не допускай открытых редиректов на вредоносные сайты.

Публичные SEO-данные должны быть доступны поисковым роботам, но административные данные должны оставаться закрытыми.

20. Анализ и проверка SEO

Перед запуском проверь:

* Все публичные URL.
* Title.
* Description.
* H1.
* Canonical.
* Sitemap.
* Robots.txt.
* Статусы страниц.
* Редиректы.
* Структурированные данные.
* Open Graph.
* Alt.
* Мобильную версию.
* Скорость загрузки.
* Отсутствие дублей.
* Отсутствие технических страниц в индексе.

Используй доступные инструменты проверки:

* Google Rich Results Test.
* Schema Markup Validator.
* PageSpeed Insights.
* Яндекс Вебмастер после подключения.

Если какой-то сервис еще не подключен, укажи это отдельно.

Не имитируй результаты внешних проверок.

21. Критерии готовности

Считай эту часть реализованной после проверки:

1. У всех публичных страниц есть корректные URL.
2. Каждая страница может иметь собственный Title.
3. Каждая страница может иметь собственный Description.
4. Курсы имеют отдельные SEO-настройки.
5. Sitemap.xml генерируется автоматически.
6. Robots.txt настроен корректно.
7. Canonical работает правильно.
8. Есть 301-редиректы.
9. Есть страница 404 с корректным HTTP-статусом.
10. Есть Open Graph.
11. Реализована подходящая Schema.org-разметка.
12. Есть хлебные крошки.
13. Есть управление Alt-текстами.
14. Есть SEO-раздел в админке.
15. Есть предпросмотр сниппетов.
16. Есть предупреждения о SEO-ошибках.
17. Админка закрыта от индексации.
18. Черновики не попадают в sitemap.
19. Изображения оптимизированы.
20. Сайт адаптирован под мобильные устройства.
21. Нет критических проблем с загрузкой.
22. Подготовлено подключение Яндекс Вебмастера.
23. Подготовлено подключение Google Search Console.
24. Все SEO-настройки сохраняются в базе данных.
25. Не используются выдуманные адреса, отзывы и характеристики.

22. Итоговое требование

Создай SEO-систему, которая позволит продвигать не только главную страницу, но и отдельные направления обучения.

Сайт должен иметь техническую основу для локального продвижения в Туймазах и ближайших городах.

При этом не пытайся искусственно манипулировать поисковой выдачей.

Главный приоритет:

Полезный контент + правильная структура + локальная релевантность + техническое качество + высокая скорость загрузки.

После реализации составь отчет:

* Что сделано.
* Какие SEO-функции работают.
* Какие инструменты подключены.
* Какие настройки еще нужно заполнить.
* Какие действия необходимы владельцу перед началом продвижения.
